Shift Lifecycle — does Open → Closed → Accepted feel right?

Question this demo answers: does the D6 shift model from the RMS reference doc hold up under real cases? One open shift per till and per cashier. Closing always uses the current moment (no backdated close). Closing just freezes a cash count — it does not touch the ledger. Acceptance is the only step that posts to GL, and it is where a back-office reviewer can override which account each line lands on before it becomes fact. A cash variance is never a soft warning — it is a mandatory GL line the reviewer cannot remove, only redirect. Once accepted, a shift cannot be cancelled: the only shift that can be freely cancelled is one still Open, since nothing downstream depends on it yet.
